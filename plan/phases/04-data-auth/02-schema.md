# 4.2 Schema + first migration

**Status:** done (#47, 3 Nov 2026; approved and external review addressed 3 Nov 2026)
**Phase:** 04-data-auth

## Goal

Every table the app needs through Phase 4, in one reviewed migration (`0001`), with the database itself refusing bad rows: foreign keys with deliberate `ON DELETE`, `NOT NULL` by default, `CHECK`s on statuses, ratings and money, and unique constraints where a duplicate would be a bug.

No app code reads or writes these tables yet. 4.4 wires up Better Auth, 4.5 the data layer, 4.8 and 4.9 fill them.

## Decisions for you

1. **Auth tables are generated by Better Auth's own CLI, not hand-written.** I add `better-auth` (1.7.x) now with a minimal `src/server/auth/auth.ts` (Drizzle adapter, `twoFactor` plugin, database rate-limit storage, an `is_synthetic` field on the user). The CLI's `generate` writes the Drizzle tables from that config, so the columns match exactly what the library reads and writes. The config isn't mounted on any route until 4.4, which then extends the same file. The alternative (hand-write from the docs now, check in 4.4) risks a corrective migration on day one of 4.4.
2. **Snake case in Postgres, camel case in TypeScript.** Drizzle's `casing: "snake_case"` in both `getDb()` and `drizzle.config.ts`, and plural table names (Better Auth's `usePlural`). The data video then reads `policies.customer_id`, not `"policy"."customerId"`.
3. **IDs: `uuidv7()` for our tables, Better Auth's text IDs for its own.** Postgres 18 has `uuidv7()` built in: time-ordered, so inserts land at the end of the index instead of all over it like a random v4. Neon, CI and local Docker all run 18 (4.1, decision 4). Auth tables keep the library's default text IDs, so foreign keys to `users.id` are `text`.
4. **A `customers` table, separate from `users`.** `users` is the login (Better Auth's). `customers` is the person who buys cover: name, date of birth, address, phone. Staff have a user, a `staff_members` row (decision 18) and no customer row. A customer row is created at the first saved quote (5.6), so its fields can be `NOT NULL`.
5. **Quotes always belong to a customer.** A guest's quote lives in the browser until the sign-in gate (5.6), then it's saved. So `quotes.customer_id` is `NOT NULL`, and nothing has to clean up abandoned guest rows.
6. **Product details hang off the quote item, and the database checks the product matches.** One quote has one item per product (car + home = a bundle). Each item has its detail rows: car → one `vehicles` row + 1–n `drivers`; home → one `properties` row; business → one `businesses` row. Each detail table has a fixed `product` column (`check (product = 'car')`) and a composite foreign key to `quote_items (id, product)`, so a `vehicles` row on a home item is refused by Postgres, not just by Zod. The quote item is the priced snapshot; a policy points at the item it was bought from.
   - **Trade-off:** mid-term changes (add a driver to a live policy, 6.3 and Kerbie in 7.5) can't edit these rows without changing quote history. They'll be a new "adjustment" quote item linked to the policy, which is also how real insurers re-rate a change. That's designed in 6.3; nothing here blocks it.
7. **`claims.customer_id` is stored and kept consistent by a composite foreign key** to `policies (id, customer_id)`. Scoped queries (4.5) filter claims by the session's customer in one indexed lookup, and a claim can never point at someone else's policy.
8. **Append-only `claim_events` and `underwriting_decisions`, enforced by a trigger** that refuses `UPDATE` (`audit_log` refuses `DELETE` too, decision 15) (deletes still cascade when a claim or quote goes with its account in 4.7). It's a small hand-written migration (`0002`, `drizzle-kit generate --custom`). 4.5 reuses the same function for `audit_log`.
9. **`reviews` comes forward from 6.7.** The phase's 4.2 test list includes "rating 6" and "one review per policy", and §8 lists both, so the table belongs with the other constraints. 6.7 builds the UI on it. I'll update its row.
10. **`is_synthetic` lives on `users` only.** Every synthetic row hangs off a synthetic user, so the data video filters with one join, and there's no flag to forget on a new table.
11. **Deleting things.** `RESTRICT` on anything that is history: a customer with policies, a policy with claims, a quote item with a policy. `CASCADE` for what a user owns outright and is meaningless alone: sessions, accounts, a quote's items and details, a claim's events. Delete account (4.7) therefore removes claims and policies explicitly in one transaction, on purpose, rather than by accident through a cascade.
12. **Underwriting is separate from pricing, per quote item** (added 2 Nov 2026 after reviewing pricing/underwriting advice). Each item has an `outcome`: `quoted` (has a price), `referred` (a claims handler must look at it) or `declined` (doesn't fit the product). Per item, because a bundle can quote the car and decline the home. The current outcome sits on `quote_items`; every decision, automatic or by a handler, is a row in append-only `underwriting_decisions`. A handler approves a referral with an optional loading (surcharge, 0–100%) or declines it, in the staff referral queue (new slice 6.11). The rules that decide the outcome are pure functions next to `priceQuote()` in 5.4, and never use sensitive personal characteristics.
13. **`rating_versions` exists from 4.2, filled in 4.8.** One row per product and version, with a status (`draft` / `active` / `retired`) and effective dates; Postgres allows only one `active` version per product. Each quote item points at the version that rated it (each product has its own tables, so the version is per item, not per quote), and changing rates later never changes an issued quote. 4.8's factor tables point at it too.
14. **Quote totals reconcile in Postgres.** `quotes` gains `fees_pence` (the pricing formula has "+ fees" and the first draft had no column), and a `CHECK` makes `total = subtotal − bundle discount + fees + IPT`, with the discount never above the subtotal. The UI shows these columns and never recomputes them.
15. **`audit_log` comes forward from 4.5, ready for a hash chain** (agreed 2 Nov 2026). Its rows can never be updated or deleted (the `0002` trigger, `UPDATE` and `DELETE` both refused, unlike the two history tables above, whose rows go when their parent does). Each row will store the previous row's hash and its own (`sha256(prev_hash ‖ row contents)`); the 4.5 `audit()` helper computes them, one insert at a time under a transaction-scoped advisory lock. Postgres refuses a fork (`prev_hash` is unique, nulls not distinct, so only one row starts the chain) and a link to a row that doesn't exist. What this does and doesn't prove: the triggers stop the app editing or deleting rows, and a broken chain shows an edit made around them. Someone who owns the tables can still drop the triggers and recompute every hash; closing that is 4.5's job (a non-owner app role, and a keyed hash or the latest hash kept outside the database). `actor_user_id` and `entity_id` are plain text with **no foreign key**: deleting an account (4.7) keeps its audit rows with the user id and nothing else about the person, and the hashes stay valid. Rows hold ids and the names of changed fields, with values only for fields that aren't personal data (an address change records that `address_line1` changed, not the address), never emails, addresses or chat text, because audit rows can't be erased (4.7) ([engineering.md §9](../../engineering.md#9-security)). High-volume sign-in events go in their own unchained table in 4.4, so bots can't flood the chain.
16. **Built for the Azure + Databricks pipeline (Phase 9)** (agreed 2 Nov 2026). Every table can be copied incrementally and nothing changes silently:
    - **Deletes leave a tombstone.** A trigger on every table writes `(table_name, row_id, deleted_at)` to `deleted_rows`, so a watermark copy learns about deletes too, and "delete my account" reaches the lakehouse (GDPR erasure downstream). One generic `record_delete()` function in `0002`, attached to every table except `deleted_rows` itself and the auth tables Better Auth churns (`sessions`, `verifications`, `auth_rate_limits`), which the pipeline doesn't copy.
    - **Every table has a change column:** mutable tables an indexed `updated_at`; append-only tables `created_at` (or the identity `id`).
    - **Analysable shapes:** the price breakdown is rows in `quote_item_factors`, not only JSON; `properties.security` becomes typed columns.
    - **Location without the address:** a generated, stored `postcode_district` (e.g. `SW1A`) on `customers` and `quotes`; the pipeline copies the district, never the full postcode.
    - **Funnel timing from day one:** `events` comes forward from Phase 7 so Phase 5 records quote started → priced → referred → bought as it happens.
    - **No timestamp is forced to `now()`:** defaults only, so the 4.9 seed can backdate 12 months of history.
17. **A data contract, enforced by a test.** `src/server/db/data-contract.ts` lists, for every table: its grain (what one row is), primary key, change column, `mutable` or `append-only`, whether it's copied to the lakehouse, and each personal-data column with its downstream treatment (`drop`, `hash`, or `bucket`, e.g. date of birth → age band, postcode → district). A unit test reads the Drizzle schema and fails CI if a table or column is missing from the contract, a contract entry names a column that doesn't exist, or a copied table has no change column. Phase 6 and 7 tables can't be added without their data side, the same way the drift check guards migrations.
18. **Staff live in `staff_members`, the single source of a user's role** (agreed 2 Nov 2026). A user with no `staff_members` row is a customer; there is no `users.role`, so the role can't disagree between two tables.
    - **Staff are deactivated, never deleted.** `staff_members.user_id` is `RESTRICT` from `users`, so deleting a staff user is refused while the row exists; deactivation (6.8) sets `deactivated_at`, revokes their sessions and returns their open claims to the queue. History stays attributed.
    - **The database refuses non-staff in staff columns.** `claims.assigned_handler_id` and `underwriting_decisions.decided_by` point at `staff_members`, not `users`. `claim_events.actor_user_id` stays on `users`, since customers write events too.
    - **`requireRole()` (4.5)** reads `staff_members` and refuses anyone deactivated. 4.5 also adds the **conflict-of-interest rule**: a staff action on a record that belongs to the staff member's own customer row is refused (an admin can hold a policy, but can't handle their own claim or approve their own referral).
    - **Data side:** the pipeline copies the user id (a pseudonym once names and emails are dropped, treated like every other user id), `staff_code`, role and dates, never the display name, so Phase 9 can join decisions, assignments and settlements to a handler and model workload and decision times.
    - `vp run auth:make-admin <email>` (4.5) inserts the `staff_members` row.
19. **Every field in the high-fidelity wireframes has a column** (checked against the Figma Quote & Policy and Claims frames, 2 Nov 2026; "don't lose any data"). The additions:
    - **Every cover tier offered is stored**, not only the chosen one: `quote_item_options` (Essential / Comprehensive / Plus, each priced), and the item points at its selected option. The data side gets "offered vs picked".
    - **Add-ons** (UK 24/7 breakdown, motor legal): `quote_item_addons`, offered and selected, each priced.
    - **Excess split** into compulsory + voluntary on items' options and policies.
    - **Pay annually or monthly:** `quotes.payment_plan` and a `payments` row per charge (a monthly plan writes the 11 future instalments as `scheduled`). Card brand and last four digits only.
    - **Each tick box is a timestamp:** details confirmed, cover understood, terms accepted, claim declaration.
    - **Policy management:** `auto_renew`, `renewal_of_policy_id` (retention data), `customers.paperless`.
    - **Vehicle and driver details shown in the "Found Volkswagen Golf…" line:** fuel type, doors, current mileage, occupation.
    - **Home cover has its own address** on `properties` (the insured property may not be where the customer lives).
    - **Draft claims** ("Save and exit"), full incident details (time, place, what happened, chips, police), third-party details, the declaration, customer ↔ staff messages, and the settlement (approved value − excess = payout, payee, last four digits, dates).
    - **Notifications** behind the header bell, for every screen.
    - **References match Figma:** `KRB-Q-#####` (quote), `KRB-######` (policy), `KRB-C-#####` (claim), each format checked by `CHECK`.
    - **Not in the database, on purpose:** cover feature lists, exclusions and the product information PDF are product content in code, versioned with the rating version; the certificate, schedule and settlement letter are generated on demand (6.2) from these rows.

## In scope

### Packages

- `better-auth` (dependency). The CLI runs with `pnpm dlx` once to generate the schema; it isn't a dependency.

### Schema (`src/server/db/schema/`)

`schema.ts` becomes a folder, one file per area, re-exported from `index.ts` (so `./schema` imports keep working).

**`auth.ts`** (generated, decision 1; then reviewed)
- `users`: Better Auth's columns, plus `two_factor_enabled` (plugin) and `is_synthetic` (default false). No role column (decision 18).
- `sessions`, `accounts`, `verifications`, `two_factors`: as generated. Foreign keys to `users` `ON DELETE CASCADE`; indexes on `user_id` and `verifications.identifier`.
- `auth_rate_limits`: Better Auth's database rate limiter (its `rateLimit` model, renamed).

**`customers.ts`**
- `customers`: `id`, `user_id` (unique, `CASCADE`), `first_name`, `last_name`, `date_of_birth` (`date`), `phone` (nullable), `address_line1`, `address_line2` (nullable), `town`, `postcode`, `postcode_district` (generated, decision 16), `paperless` (default true), `created_at`, `updated_at`.

**`staff.ts`** (decision 18)
- `staff_members`: `user_id` (primary key, `RESTRICT` from `users`), `role` (`claims_handler` / `admin`), `display_name` (what customers see, e.g. "Sam from Kerb claims"), `staff_code` (unique, `H-` + 3 digits, the pseudonymous id the pipeline copies), `started_at`, `deactivated_at` (nullable; `CHECK` after `started_at`), `created_at`, `updated_at`. Index on `role`.

**`quotes.ts`**
- `quotes`: `id`, `reference` (unique, `KRB-Q-#####`, format `CHECK`), `customer_id` (`CASCADE`: a draft is the customer's own), `status` (`draft` / `priced` / `referred` / `declined` / `accepted` / `expired`), `postcode`, `postcode_district` (generated), `subtotal_pence`, `bundle_discount_pence`, `fees_pence`, `ipt_pence`, `total_pence` (all `≥ 0`; reconcile `CHECK` and discount ≤ subtotal, decision 14; the subtotal is the selected options plus selected add-ons), `payment_plan` (nullable until chosen: `annual` / `monthly`), `details_confirmed_at`, `cover_acknowledged_at` (nullable; "I confirm these details are correct", "I understand my cover"), `valid_until`, `created_at`, `updated_at`. Unique `(id, customer_id)` (target of `payments`' composite key).
- `quote_items`: `id`, `quote_id` (`CASCADE`), `product` (`car` / `home` / `business`), `rating_version_id` (`RESTRICT`, decision 13), `outcome` (`quoted` / `referred` / `declined`, indexed for the referral queue), `reason_code` (nullable; `CHECK` it's set unless `quoted`), `selected_option_id` (nullable; composite foreign key `(selected_option_id, id)` to `quote_item_options (id, quote_item_id)`, so the choice must be one of this item's own options), `voluntary_excess_pence` (`≥ 0`), `start_date`, `created_at`, `updated_at`. Unique `(quote_id, product)` (one car per quote) and `(id, product)` (target of decision 6's foreign keys).
- `quote_item_options` (decision 19): `id`, `quote_item_id` (`CASCADE`), `cover_level` (e.g. `essential` / `comprehensive` / `plus`; values checked by Zod per product), `cover_multiplier` (`numeric(8,4)`, `> 0`: the tier's factor), `compulsory_excess_pence` (`≥ 0`), `annual_premium_pence`, `monthly_premium_pence` (`> 0`), `created_at`. Unique `(quote_item_id, cover_level)` and `(id, quote_item_id)`. Every tier offered is a row, chosen or not.
- `quote_item_addons` (decision 19): `id`, `quote_item_id` (`CASCADE`), `addon` (e.g. `breakdown_uk`, `motor_legal`), `annual_price_pence`, `monthly_price_pence` (`> 0`), `selected` (default false), `created_at`, `updated_at`. Unique `(quote_item_id, addon)`.
- `quote_item_factors` (decision 16): `id` (identity), `quote_item_id` (`CASCADE`), `factor` (e.g. `insurance_group`, `driver_age`, `occupation`, `postcode_band`), `input_value` (text, the band or value used), `multiplier` (`numeric(8,4)`, `> 0`), `created_at`. Unique `(quote_item_id, factor)`. The factors shared by every tier; each tier's own factor is on its option. The summary's breakdown (5.5) is built from these rows, so it's stored once.

**`underwriting.ts`** (decisions 12 and 13)
- `rating_versions`: `id`, `product`, `version` (int; unique with `product`), `status` (`draft` / `active` / `retired`), `effective_from`, `effective_to` (nullable; `CHECK` after `effective_from`), `notes` (nullable), `created_at`. Partial unique index: one `active` per product.
- `underwriting_decisions`: `id` (identity), `quote_item_id` (`CASCADE`, indexed), `outcome` (same three values), `reason_code` (nullable; `CHECK` it's set unless `quoted`), `loading_percent` (nullable `smallint`, `CHECK` 0–100), `decided_by` (nullable, foreign key to `staff_members`; null means the automatic rules), `note` (nullable), `created_at`. Append-only (decision 8).

**`products.ts`** (detail tables, decision 6; all `CASCADE` from their item)
- `vehicles`: `quote_item_id` (unique), catalogue fields copied at quote time (`make`, `model`, `year`, `variant`, `fuel_type` (`petrol` / `diesel` / `hybrid` / `electric`), `doors` (2–7), `insurance_group` 1–50, `value_pence`), `registration` (nullable), `current_mileage` (odometer, `≥ 0`), `annual_mileage` (`> 0`), `usage` (`social` / `commuting` / `business`), `overnight_location` (`garage` / `driveway` / `street`).
- `drivers`: `quote_item_id`, `is_main`, `first_name`, `last_name`, `date_of_birth`, `occupation` (text; the list is checked by Zod and rated in 4.8), `licence_years` (`≥ 0`), `no_claims_years` (`≥ 0`), `past_claims` (`≥ 0`). One main driver per item (partial unique index).
- `properties`: `quote_item_id` (unique), the insured address (`address_line1`, `address_line2` (nullable), `town`, `postcode`, `postcode_district` (generated)), `property_type` (`detached` / `semi` / `terraced` / `flat` / `bungalow`), `year_built`, `bedrooms` (`≥ 0`), `rebuild_cost_pence`, `contents_value_pence`, `has_alarm`, `has_smoke_alarm`, `lock_type` (`standard` / `five_lever` / `multipoint`), `past_claims`.
- `businesses`: `quote_item_id` (unique), `trade_class`, `turnover_pence`, `employees` (`≥ 0`), `cover_sections` (`text[]`).

**`policies.ts`**
- `bundles`: `id`, `customer_id` (`RESTRICT`), `quote_id` (unique), `created_at`.
- `policies`: `id`, `reference` (unique, `KRB-######`, format `CHECK`), `customer_id` (`RESTRICT`), `quote_item_id` (unique, `RESTRICT`: one policy per quoted product), `bundle_id` (nullable, `RESTRICT`), `renewal_of_policy_id` (nullable, unique, `RESTRICT`: the policy this one renews), `product`, `cover_level`, `status` (`active` / `cancelled` / `lapsed`), `starts_on`, `ends_on` (`CHECK ends_on > starts_on`), `annual_premium_pence`, `compulsory_excess_pence`, `voluntary_excess_pence` (`≥ 0`; the total excess is their sum), `auto_renew` (default true), `terms_accepted_at`, `version` (int, default 1), `cancelled_at`, `created_at`, `updated_at`. Unique `(id, customer_id)` for decision 7. Selected add-ons are read through `quote_item_id`.
- `payments` (decision 19): `id`, `customer_id` + `quote_id` (composite foreign key to `quotes (id, customer_id)`, `RESTRICT`: the accepted quote, which covers every policy in a bundle), `plan` (`annual` / `monthly`), `instalment_number` (1–12; `CHECK` 1 when `annual`), `amount_pence` (`> 0`), `status` (`scheduled` / `succeeded` / `failed` / `refunded`), `card_brand`, `card_last4` (`CHECK` four digits; never a full number or expiry), `due_on`, `paid_at` (nullable; `CHECK` set exactly when `succeeded` or `refunded`), `created_at`, `updated_at`. Unique `(quote_id, instalment_number)`; indexes on `status` and `due_on`. Fake payments only.

**`claims.ts`**
- `claims`: `id`, `reference` (unique, `KRB-C-#####`, format `CHECK`), `policy_id` + `customer_id` (composite foreign key to `policies`, `RESTRICT`), `status` (`draft` / `received` / `assessing` / `approved` / `declined` / `settled`; §8's rulebook gains `draft → received`), `incident_type` (`collision` / `theft` / `glass` / `other`; home types join with the home claim journey), and, all nullable while `draft`: `incident_at` (date and time), `incident_location`, `description` (`CHECK` at most 2,000 characters), `declaration_accepted_at`, `submitted_at`. `CHECK`: once out of `draft`, all five are set. Also `other_vehicle_involved`, `rear_ended`, `injuries`, `police_attended` (default false), `police_reference` (nullable; `CHECK` only when `police_attended`), `claimed_amount_pence` (nullable, `≥ 0`), `assigned_handler_id` (nullable, foreign key to `staff_members`), `version`, `created_at`, `updated_at`.
- `claim_events`: `id` (identity), `claim_id` (`CASCADE`), `type` (`submitted` / `status_changed` / `details_checked` / `note` / `file_added` / `settlement_scheduled` / `settlement_paid`), `visibility` (`customer` / `internal`: the tracker shows only `customer` rows; staff notes are `internal`), `from_status`, `to_status` (nullable, same values as `claims.status`), `note`, `actor_user_id` (nullable, `SET NULL`), `created_at`. Append-only (decision 8).
- `claim_third_parties` (decision 19): `id`, `claim_id` (`CASCADE`), `name`, `registration`, `insurer_name`, `policy_number`, `phone` (all nullable; `CHECK` at least one is set), `created_at`, `updated_at`. Personal data about someone who isn't our customer, so the data contract drops it.
- `claim_messages` (decision 19): `id`, `claim_id` (`CASCADE`), `sender_user_id` (nullable, `SET NULL`), `sender_kind` (`customer` / `staff`), `body` (`CHECK` at most 2,000 characters), `read_at` (nullable), `created_at`. Index `(claim_id, created_at)`.
- `claim_settlements` (decision 19): `id`, `claim_id` (unique, `CASCADE`), `approved_amount_pence`, `excess_pence`, `payout_pence` (`≥ 0`; `CHECK payout = GREATEST(approved − excess, 0)`), `payee_name`, `account_last4` (`CHECK` four digits), `status` (`scheduled` / `paid`), `expected_on`, `paid_at` (nullable; `CHECK` set exactly when `paid`), `approved_by` (foreign key to `staff_members`), `created_at`, `updated_at`.

**`reviews.ts`**
- `reviews`: `id`, `policy_id` (unique: one review per policy) + `customer_id` (composite foreign key to `policies (id, customer_id)`, like claims, so a review can't belong to someone who doesn't hold the policy; `CASCADE`), `rating` (`smallint`, `CHECK 1–5`), `title`, `body`, `status` (`pending` / `published` / `rejected`), `moderation_reason` (nullable), `published_at`, `created_at`, `updated_at`.

**`audit.ts`** (decision 15; written to from 4.5)
- `audit_log`: `id` (identity), `created_at`, `actor_user_id` (nullable text, no FK; null = the system), `actor_role` (nullable, the role at the time), `action` (`CHECK` format `area.verb`, e.g. `claim.status_changed`, `referral.approved`, `claim.viewed`), `entity_type`, `entity_id` (text, no FK), `changes` (`jsonb`, nullable: before/after of the changed fields only), `reason` (nullable), `request_id` (nullable), `ip_hash` (nullable; a hash, never the address), `prev_hash` (nullable only for the first row), `hash` (unique). Indexes: `(entity_type, entity_id)`, `actor_user_id`, `action`, `created_at`.

**`data.ts`** (decision 16)
- `deleted_rows`: `id` (identity), `table_name`, `row_id` (text; composite keys joined with `:`), `deleted_at`. Index on `deleted_at` (the pipeline's watermark). Written only by the `record_delete()` trigger.
- `events`: `id` (uuidv7), `occurred_at`, `name` (`CHECK` format `area.verb`, e.g. `quote.started`, `quote.priced`, `policy.bought`, `claim.opened`), `user_id` (nullable text, no FK: events outlive accounts the way audit rows do), `anonymous_id` (nullable; PostHog's distinct id, so the two can be joined), `entity_type`, `entity_id` (nullable), `properties` (`jsonb`, no personal data), `created_at`. Indexes on `(name, occurred_at)` and `user_id`. Append-only.

**`notifications.ts`** (decision 19)
- `notifications`: `id`, `user_id` (`CASCADE`), `type` (`CHECK` format `area.verb`, e.g. `claim.updated`, `referral.decided`, `payment.failed`, `policy.renewal_due`), `title`, `body`, `link_path` (nullable; `CHECK` starts with `/`, an in-app link only), `read_at`, `email_sent_at`, `sms_sent_at` (nullable; set by the 4.11 jobs that send them), `created_at`. Index `(user_id, read_at)`.

**`platform.ts`** (§8, §10, §11; their code comes in 4.5 and 4.11)
- `idempotency_keys`: `user_id` + `key` (primary key; `CASCADE` from users), `request_hash`, `response` (`jsonb`, null while in flight), `created_at`, `expires_at` (indexed for cleanup).
- `rate_limits`: `key` + `window_start` (primary key), `count` (`≥ 0`). The app's sliding-window counter; Better Auth's limiter has its own table above.
- `jobs`: `id` (identity), `type`, `payload` (`jsonb`), `status` (`queued` / `running` / `done` / `failed` / `dead`), `attempts` (`≥ 0`), `run_after`, `last_error`, `idempotency_key` (unique), `created_at`, `updated_at`. Index `(status, run_after)` for the runner.

**`relations.ts`**: Drizzle `relations()` for the core tables, so 4.5's queries load a policy with its claims in one query, not N+1.

**Everywhere:** `NOT NULL` unless listed as nullable; times are `timestamptz` (defaults `now()`); `updated_at` set by Drizzle's `$onUpdate`; money is `integer` pence; indexes on every foreign key and on `status` and `created_at` where 4.5–6.10 filter or sort by them (`policies`, `claims`, `quotes`, `reviews`, `jobs`).

## Notes from the build

Calls made while building, beyond the spec's text:

- **Better Auth's CLI is the `auth` package** (`pnpm dlx auth@1.7.15 generate`); `@better-auth/cli` stopped at 1.4. The generated tables were reviewed and changed: `timestamptz`, `NOT NULL` on `two_factor_enabled` and `is_synthetic`, snake-case index names, `updated_at` indexes, relations moved to `relations.ts`. Re-running the CLI means carrying these over (comment at the top of `schema/auth.ts`).
- **Constraint names are explicit for unique constraints.** drizzle-kit builds them from the TS key (`policies_quoteItemId_unique`) even with `casing`; the schema names them in snake case.
- **`updated_at` added** to `rating_versions`, the product detail tables, `claim_messages` and `notifications`: their rows change (status, drafts, `read_at`), and decision 16 gives every mutable table a change column.
- **`policies` points at `quote_items (id, product)`**, so a policy's product always matches the item it was bought from (decision 6's guarantee, extended).
- **Append-only vs `SET NULL`:** `claim_events.actor_user_id` is `SET NULL` when the account goes, which is an `UPDATE`. History rows (`claim_events`, `underwriting_decisions`) use `refuse_direct_change()`: an `UPDATE` or `DELETE` is allowed only when a foreign-key action fires it (`pg_trigger_depth() > 1`), so cascades and `SET NULL` work and a direct statement is refused. `audit_log` refuses both outright. Refusals raise `42501` (`insufficient_privilege`); Postgres already uses `23001` for `ON DELETE RESTRICT`.
- **Not copied to the lakehouse** (no `record_delete` trigger): besides the spec's `sessions`, `verifications`, `auth_rate_limits` and `deleted_rows`, also `two_factors` (TOTP secrets, no change column) and the operational `idempotency_keys`, `rate_limits` and `jobs`. The data contract records this; the integration test checks the triggers match it exactly.
- **Nullable where the list was open:** `claim_events.note` and `from_status`, `reviews.published_at`, and `events.entity_type` (set together with `entity_id`).
- **Extra refusals:** a payment whose quote isn't the customer's; a protocol-relative notification link.

### External review (3 Nov 2026): changes before merge

- **The audit chain can't fork** (H1): `prev_hash` is unique with nulls not distinct, has a foreign key to `hash`, and both are checked as 64 hex characters. Decision 15 is reworded so it doesn't promise tamper-evidence against the table owner.
- **One rule for user ids** (H2): every user-id column is `keep` in the data contract, `staff_members.user_id` included; a unit test checks it across every foreign key to `users` and `staff_members`. Decision 18's data side is reworded.
- **Free text isn't copied** (H3): `audit_log.changes` and `reason`, `underwriting_decisions.note` and `reviews.moderation_reason` are `drop`. Decision 15 now records personal-data fields by name only.
- **History rows change only through a foreign-key action** (M1; see above).
- **Watermarks** (M3): a `set_updated_at()` trigger on every table with `updated_at`, so raw SQL and `SET NULL` move it (a value the writer sets is kept, for the seed); every table the contract calls append-only refuses `UPDATE`. Transaction-time timestamps are a Phase 9 concern (its 9.3 row).
- **Ownership by composite keys** (M4): `policies.quote_id` (new) ties a policy to its customer's quote and to an item on that quote; `bundles` to the customer's quote; a policy's bundle to its quote; a quote item's rating version to its product; a renewal to one of the customer's own policies, never itself.
- **`/\host` links refused** (M5): browsers read them as `//host`.
- **Statuses agree with their timestamps:** cancelled ⇔ `cancelled_at`, published ⇔ `published_at`; an accepted quote has a payment plan and both confirmations; a `status_changed` event has a `to_status`; a loading only on a `quoted` decision.
- **Also:** an index on `quote_items.selected_option_id`; every trigger function pins `search_path`; the hero width test waits for `document.fonts.ready`.
- **Follow-ups, recorded in their slices:** a non-owner app role, a keyed hash or an external anchor, and `audit()` timing (4.5: M2, M6); a Better Auth sign-up, sign-in and 2FA test against these tables (4.4); an overlap window for watermark copies (9.3).
